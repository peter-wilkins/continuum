# Bluetooth Headset UX

## Core idea

Continuum should work naturally through a Bluetooth headset as an always-available continuity interface.

The headset experience should feel:

- lightweight
- low-friction
- ambient
- conversational
- cognitively calm

The user should be able to externalise thoughts with minimal interruption to real-world activity.

---

# Product philosophy

The Bluetooth headset is not primarily a voice assistant interface.

It is:

> a continuity interface between thought and persistent context.

The goal is to reduce the friction between:

- thought
- capture
- retrieval
- continuation

without forcing the user into explicit software interaction.

---

# Desired interaction model

The ideal experience is:

```text
thought
→ short spoken capture
→ automatic contextual organisation
→ later contextual resurfacing
```

The user should not need to:

- unlock phones repeatedly
- navigate interfaces
- manage folders
- manually organise information
- maintain databases of thoughts

---

# Bluetooth workflow goals

## Passive availability

The headset should allow Continuum to feel:

- instantly accessible
- always nearby
- low-effort
- interruption-friendly

The user should feel able to capture thoughts during:

- walking
- driving
- chores
- commuting
- transitions between tasks
- moments of spontaneous insight

---

## Extremely low activation friction

The ideal capture flow should require:

- minimal taps
- minimal wake-up steps
- minimal device interaction

Potential flows:

- headset button triggers capture
- voice activation phrase
- automatic continuation after pause detection
- conversational shorthand

---

# Conversational shorthand

Over time, the user and system may develop compressed language patterns.

Examples:

- "Continue Jenkins"
- "Supplier issue again"
- "Bathroom thread"
- "Capture this"

The AI should gradually learn:

- recurring projects
- emotional context
- shorthand references
- active concerns
- likely intent

---

# Retrieval philosophy

Bluetooth retrieval should optimise for:

- rapid orientation
- calm summaries
- continuity restoration
- short spoken context

Examples:

```text
"Jenkins project:
waiting for revised quote.
Supplier confidence still low.
You planned to follow up Friday."
```

The system should prioritise:

- concise responses
- momentum restoration
- low cognitive load

rather than long conversational output.

---

# Layered retrieval model

Voice retrieval should support progressive disclosure.

Example:

```text
User:
"What's going on with Jenkins?"

AI:
"Main issue is supplier delays.
Customer waiting on revised pricing."

User:
"More detail."
```

This prevents cognitive overload.

---

# Trust model

All spoken captures should enter the immutable append-only source log.

The user should trust that:

- thoughts are preserved
- context is recoverable
- AI summaries are layered above source truth
- important ideas are not silently lost

This trust is essential for cognitive release.

---

# Calmness and outward focus

The Bluetooth experience should encourage:

- outward engagement with life
- reduced cognitive clutching
- mental decompression
- trusted external continuity

The system should help the user:

> safely release thoughts from working memory.

The goal is not constant self-analysis.

The goal is continuity with calmness.

---

# Anti-patterns

Avoid turning the Bluetooth workflow into:

- endless chatter with AI
- constant interruptions
- notification overload
- productivity theatre
- recursive self-analysis
- high-maintenance voice commands

The system should remain:

- quiet
- ambient
- sparse
- useful
- grounding

---

# Long-term vision

The Bluetooth headset experience should eventually feel like:

- an external continuity layer
- an operational memory companion
- a calm cognitive prosthetic
- a trusted place for unfinished thoughts

The user should feel:

> "I can let go of this thought now. The system will help me continue later."
